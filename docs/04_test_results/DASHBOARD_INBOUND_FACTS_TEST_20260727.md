## 3. 확정된 업무 계약

### 3.1 정상입고와 반품

- 업무코드 그룹은 `0012`를 사용한다.
- 정상입고 Tcode는 `001`, `002`만 인정한다.
- 정상입고 이벤트는 `Quantity + Oquantity > 0`인 행만 인정한다.
- 동일 제품과 동일 거래일은 정상입고 거래일 1일로 중복 제거한다.
- `051`, `061`, `090` 및 음수 정정 또는 취소만 존재하는 날짜는 정상입고일로 인정하지 않는다.
- 입고반품 Tcode는 `101`, `102`, `193`이며 원본 부호를 그대로 집계한다. 반품에 추가 음수 부호를 곱하지 않는다.

### 3.2 기간과 지연 판정

- 입고 이력 기간은 최근 365일이다.
- 실제 입고 기반 대표 매입처 기간은 최근 90일이다.
- 평균 입고간격은 제품별 고유 정상입고 거래일의 인접 간격 평균이다.
- 지연 기준일은 `max(평균 입고간격 x 2, 14일)`이다.
- 입고 경과일이 지연 기준일보다 큰 경우 지연 후보로 판정한다.
- 정상입고 거래일이 0일 또는 1일이면 평균 간격과 지연 판정은 자료부족으로 표시한다.

### 3.3 대표 매입처 fallback

대표 매입처는 다음 순서로 귀속한다.

1. 최근 90일 양수 정상입고가 있는 경우 실제 입고 매입처
2. 실제 입고 매입처가 없으면 제품마스터 발주처
3. 둘 다 없으면 자료없음

최근 90일 실제 입고 매입처의 순위는 수량 내림차순, 공급가액 내림차순,
최근 입고일 내림차순, 매입처코드 문자열 오름차순으로 결정한다.

### 3.4 업무코드 문자열 계약

Gcode, Tcode 및 `Gcode:Tcode`는 화면, profile, params, service, SQL bind까지
문자열로 유지한다. 선행 0을 보존하며 `"01"`과 `"1"`, `"0031"`과 `"31"`을
동일한 코드로 취급하지 않는다.

## 4. 원천 및 로직

입고 facts는 ERP 원천 `Rddbc110`에서 1회 읽기 전용 조회로 생성한다.
정상입고와 반품은 SQL의 Gcode/Tcode 문자열 조건으로 분리하고, 이후 pandas에서
제품별 정상입고 이벤트, 입고 간격, 실제 입고 매입처를 집계한다.

Dashboard에서 표시하는 종료일과 입고 cutoff은 분리한다.

- 평가월이 과거월이면 해당 월의 말일을 cutoff으로 사용한다.
- 평가월이 현재월 또는 미래월이면 정책일과 오늘 중 이른 날짜를 cutoff으로 사용한다.
- 표시용 `date_to`가 현재월 입고 cutoff을 이전 완료월로 되돌리지 않는다.

현재월 평가월 수동 검증에서는 cutoff이 `20260727`로 적용되어 현재월 정상입고를
포함했다. 이전의 이전 완료월 말일 cutoff 문제는 재현되지 않았다.

## 5. Company Default 조건 연결

입고 facts 원천은 Dashboard의 기존 공통 조건을 그대로 사용한다.

| 조건 | 코드그룹 | 적용 방식 |
| --- | --- | --- |
| 재고위치 | `0018` | 선택 Tcode 목록을 문자열 bind |
| 제품그룹 | `0013` | 제품 조건에 적용 |
| 제품구분 | `0004` | `Gcode:Tcode` pair 유지 |
| 제품분류 | `0031` | `Gcode:Tcode` pair 유지 |
| 거래처그룹 | `0019` | 기존 조건 계약 유지 |
| 거래처종류 | `0009` | 기존 조건 계약 유지 |
| 입출고구분 | `0012` | 정상입고/반품 whitelist와 함께 적용 |

모든 복합코드는 Gcode와 Tcode의 조합을 유지하며 숫자 변환이나 선행 0 제거를 하지
않는다. 제품분류 `0031` 계약과 특수관리제품 `0028` legacy 계약도 혼합하지 않는다.

## 9. Source Call 및 Cache 검증

최초 Dashboard 조회에서는 기존 base source 2회와 inbound source 1회가 실행되어
총 `source_call_count=3`이다.

다음 조작은 현재 세션의 cache를 재사용하며 입고 원천 SQL을 추가 실행하지 않는다.

- 위험 상세 필터
- 제품 검색
- 위험 상태 변경
- 표시 행 수 변경
- Excel 준비
- 선택 조치 인라인 상세

필터 rerun에서 chat push와 partition append가 추가로 발생하지 않으며, 기존
Dashboard 매출 및 재고 결과도 변경하지 않는다.
