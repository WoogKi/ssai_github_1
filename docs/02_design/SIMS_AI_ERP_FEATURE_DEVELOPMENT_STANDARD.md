# SIMS AI ERP 업무 개발 표준

2026-11-27 공식 기준. 신규 ERP 업무와 기존 업무 확장에 적용한다. [NLQ 개발 원칙](SIMS_NLQ_DEVELOPMENT_POLICY.md)은 업무 판별·정규 조건·안내·회귀의 상위 계약이다. 이 문서는 신규 ERP 자료원을 그 계약에 연결하는 방법을 규정하며 새로운 NLQ Action을 승인하지 않는다. 금융 적용 범위는 [통합 상세설계](SIMS_AI_ERP_PAYMENT_REDESIGN_20261127.md), 적용 순서는 [개발계획](SIMS_AI_ERP_PAYMENT_DEVELOPMENT_PLAN.md)을 따른다.

## 공통 개발 원칙

- 개발 전에 관련 업무의 실제 호출 관계를 조회 화면·NLQ에서 서비스, 결과 소비자와 인가 경계까지 추적한다. 같은 모듈을 import한 사실이 아니라 같은 공통 함수를 호출하는지 확인한다. 중복 구현이나 실패 시 우회 대신 원인을 재현하고 해당 경계를 수정한다.
- 모든 ERP 업무코드는 영문자와 선행 0을 포함할 수 있는 문자 식별자다. 값 추정이나 정수 변환을 하지 않는다. 범위 비교는 해당 업무에 승인된 ERP 비교 규칙을 따른다. 금융 0023의 경계를 다른 코드에 적용하지 않는다.
- 스키마·라벨·업무 역할은 기존 메타데이터에 등록한다. 화면과 원천 NLQ는 동일 정규 조건과 조회 서비스를 쓰고, 현재표는 검증된 전체 원본을 재조회 없이 쓴다. 공통 검색·집계·표·다운로드·분석·인가 경계를 재사용한다.
- 완료 전 등록된 전체 업무에 대한 회귀를 실행한다. 최신 사례집을 명시하고 자동 생성한 차원·별칭 질문을 원본 PK·건수·금액·그룹 키까지 대조한다. 구조 감사, DB-free 실행 및 실사용 검증을 구분하며, 미실행과 HEAD 기저 실패를 PASS로 집계하지 않는다.

## 1. 출발점: 업무 계약표 한 장

- [ ] 기준 HEAD·브랜치·기존 WIP·기존 action/alias/payload_key/메뉴 충돌을 조사한다. 기존 서비스, 형제 화면과 NLQ 호출자를 먼저 찾는다. 등록 항목에 실제 소비자가 있는지 확인한다.
- [ ] 업무명, 물리 테이블, **한 행의 의미**, 복합 PK 전부, 자료형/길이/scale/NULL, 날짜 역할, 거래처·코드의 역할, 정확한 금액과 허용되는 집계 방식을 승인 자료로 정한다. 원본일/전표일/처리월을 같은 필드로 취급하지 않는다.
- [ ] 코드표의 Gcode+Tcode, 명칭 출처, 마스터 조인 유일성, 미등록·중복 시 동작을 적는다. 1:N 명칭 연결로 사실행을 복제하지 않는다. PK는 화면상 순번이 아니다.
- [ ] 권한·회사·조회 상한·다운로드 상한, 기본 기간과 적용 시점, 허용 필터, 필수 조건, 허용 후속분석을 결정한다. 근거 없는 정책은 미확정으로 남긴다.
- [ ] 사용자에게 보여줄 명칭과 결과 열 순서·고정열을 합의한다. 컬럼의 DB 정의 순서가 화면의 업무 우선순위는 아니다.

## 3. 화면과 NLQ의 합류 계약

1. 화면은 사용자 입력/후보 선택을, NLQ는 요청한 업무 및 필드 역할을 명시한 입력을 만든다. 화면 전용 session/widget key, 원문 질문, 화면 표시 TOP을 업무 WHERE 조건과 섞지 않는다. 후보가 여럿이거나 해석 불가한 조건은 불필요하게 넓은 조회로 대체하지 않는다.
2. 서비스 진입 전후 동일한 정규화 함수를 사용한다. 예: 일 범위와 월 범위를 구분하고, 날짜 역할을 ID로 보존하고, 코드 앞자리 0과 NULL을 보존한다. 명시값 > 승인된 업무 기본값; 유효하지 않은 명시값에 기본값을 대신 쓰지 않는다. 이름과 코드를 같은 검색 연산자로 처리하지 않는다. 동일 입력에 반복 정규화해도 결과가 같아야 한다.
3. 인가에서는 로그인 사용자·선택 회사·권한·epoch의 일치를 검증한다. 조회 전 실패 시 ERP SELECT 0회. 결과 도착/게시·export 시 경계가 바뀌면 결과를 재사용하지 않는다. 금융 기본 조회는 IO_READ, Excel은 IO_READ + EXPORT_EXCEL. 새로운 역할을 만들거나 일괄 부여하지 않는다.
4. SQL은 업무 서비스가 소유한다. 값은 driver bind, 식별자/정렬은 코드가 정한 목록만 사용. 안정된 PK 순서와 자료 범위를 보장한다. 적법한 0건·조건 오류·DB 오류·초과를 구분한다. 완전성이 필요한 조회는 상한+1로 검사하고 초과분을 잘라 성공했다고 하지 않는다. 승인된 회사 연결이 없으면 공용 기본 DB로 대체하지 않는다.
5. NLQ가 아직 준비되지 않았으면 목록/도움말에 실행 가능한 업무로 광고하지 않는다. 등록된 별칭이 매칭되어도 parser와 서비스가 없으면 다른 화면이나 광범위한 ERP 조회로 우회하지 않는다. 기존표의 정렬/필터/분석과 신규 원천 조회를 별도 판별한다.
6. 조회 후 채널별 로컬 필터로 행 집합이 달라지지 않게 한다. 불가피한 업무 후처리도 공통 서비스에서 딱 한 번 적용해 원본/표시/다운로드/Facts가 동일 기준을 따른다.

## 4. 결과, 다운로드 및 분석 계약

- 전체 데이터와 표시 데이터를 분리한다. full = 현재 조건·회사 범위에서 확보하고 검증한 전체 DF; display = full에서 만든 제한된 복사본. payload에는 action, 정규 params, df, df_display, columns, 표시 records, meta(전체/표시/내보내기 행수·원천·완전성·권한 범위·분석 날짜 역할)를 연결한다. 소스가 불완전하면 전체로 표시하지 않는다. build_result_payload/build_feature_result 호출만으로 full 계약이 보장된다고 간주하지 않는다.
- 한글명과 업무 열 순서는 동일 projection으로 정한다. 순번은 소수점 없는 정수, 코드/번호는 문자(앞자리 0), 날짜는 날짜 역할에 맞는 연·월·일, NULL은 빈칸으로 표시한다. 표시 자료의 통화 기호·쉼표는 원본 값이 아니다.
- CSV 및 Excel의 출처는 full. 기존 다운로드 권한과 현재 소유자 바인딩을 확인한다. Decimal(18,0)을 float로 중간 변환하지 않는다. Excel 숫자 셀로 정밀도를 보존할 수 없는 긴 값은 손실 없는 텍스트 등 명시한 정책을 적용하고 내보낸 파일을 다시 읽어 검증한다. CSV는 문자열 원문을 확인한다.
- Current Table에는 현재 회사/사용자의 원천과 결과 식별 근거를 연결한다. 만료되거나 다른 회사로 전환되면 재사용/자동 재조회하지 않는다. 후속질문은 지원 범위와 화면 안내가 같아야 한다.
- LLM에는 전체자료에서 검증한 Facts와 허용 열만 전달한다. 분석 기준일은 조회 업무의 날짜 역할에서 정하고, 자료에 전표일이 함께 있다는 이유로 바꾸지 않는다. 표시 일부를 전체 추세로 서술하지 않는다. 정확한 합계와 행수는 프로그램이 산출하며 LLM이 계산한 값으로 대체하지 않는다.

## 5. 금융 적용 시 불변 조건

- 310: 업무코드 0023. 업무코드는 숫자로 보이더라도 문자형 식별자로 취급한다. 원 ERP SQL의 문자열 비교(`코드 < '50'` / `코드 >= '50'`)를 결과 컬럼·조건 검증·SQL 바인딩에 일치시킨다. 현재표·분석은 조회 결과의 분류를 재사용한다. 00/50은 발생금액, 32/82는 양 잔액에 영향을 주는 조정 할인. 전체 금액을 현금 수지라고 부르지 않는다.
- 320/330: 어음번호·순번으로 연관되지만 행 단위가 다르다. 여러 담보 거래를 어음 사실행으로 증식시키거나 같은 금액을 반복 합산하지 않는다.
- 260/270은 장부(기본)/실(명시 또는 비교) 월 변동의 내부 자료원이다. 사용자 Action·메뉴·View·상태 키를 만들지 않는다. 실제 원장·잔액 소비자가 생긴 단계에서만 내부 서비스를 만든다. 제품재고현황의 기존 __io260_last_payload는 변경하지 않는다. 같은 기간의 상세와 월자료를 합산하지 않는다.
- 신규 잔액 공식·NLQ·금융 권한·KPI 등은 별도 승인 없는 기본 조회에 포함하지 않는다.

- [ ] 변경 후 해당 업무와 가장 가까운 기존 110/120·230·제품재고장 및 공통 카드 회귀 범위를 정한다. 큰 라우팅 변경과 단순 폼 변경의 검증 범위를 똑같이 취급하지 않는다.

- [ ] 수정 위치·검증 결과·미검증 사항·사용자 수동 확인 절차 및 WIP 보존을 기록한다. 운영 DB 실행·배포는 별도 승인이다.

**적용 범위:** 최근 달력 한 달·입출금 관리 메뉴·조회 3종은 금융의 확정 정책이며 모든 ERP 업무에 소급 적용하지 않는다. 기준일 역할, 지원 분석과 exact reader의 구현은 업무별 검증 후 확정한다.

## R4 적용 메모 (금융 적용 사례)

전체 DF에서만 표시본을 파생하고, 원본 소유 범위와 전체 행수를 다운로드·현재표 provenance에도 전달한다. 분석 실행 시 내부 인증 메타를 확인하되 모델 입력에는 보내지 않는다. Decimal 정밀도 검증은 표뿐 아니라 CSV 바이트, XLSX 셀 값과 형식, 검증된 분석 문장까지 포함한다. 화면 이벤트는 후보검색과 본조회 클릭을 분리하여 AppTest로 검증한다. 이 메모는 L2-1의 적용 사례이며 다른 업무의 기본 정책을 바꾸지 않는다.

## R5 적용 메모 (금융 적용 사례)

화면과 후속 입력 경로는 서비스가 검증하는 같은 조건 ID를 사용한다. 명칭 검색은 기존 표시용 마스터 연결을 재사용하며 미일치를 조건 삭제로 처리하지 않는다. 합성 폼 검증에는 같은 줄에 배치된 실제 위젯, 후보검색과 본조회 분리, 즉시 게시와 이력 표시 순서, 최종 카드 행수와 완료 안내의 일치를 포함한다. 전체 다운로드·분석은 표시 제한을 적용하지 않는다.

## R5 현재표 연계 (1호기 합격)

정수 금액의 현재표는 역할·인증 범위·전체 행수를 원본 키와 묶고, 공통 dispatcher/집계/게시 경로를 사용한다. 날짜 역할을 추측하거나 화면 표시본으로 대체하지 않는다. 후속표는 원본 action의 권한, 별도 결과 키와 정확 금액 열을 유지한다. DB-free 합격 기준에 NULL·음수·18자리 합계와 1원 차이 설명 검증, 연속 후속 원본 선택, 파생표 자체의 XLSX/CSV/Facts 대조를 포함한다.

### R5 담당자 및 후속 결과 표시 보정

마스터의 현재 담당자와 원본 업무 담당자는 서로 다른 역할로 등록한다. 동명이인 집계 키는 코드와 이름을 함께 사용한다. 정확 금액 표에서 전체 원본과 표시 복사를 분리하고 파생표에는 살아 있는 날짜·정수·정확 금액·고정 컬럼 속성만 전달한다. 표·CSV·Excel에 동일한 날짜·문자 결측 정규화를 적용하되 숫자 0·원본 NULL·선행 0·금액 정밀도를 보존한다. 특정 업무 분류의 금액을 요구한 순위는 집계 전에 그 분류로 제한하고 다른 분류 금액을 섞지 않는다.

### Current Table 집계 표현 검증

질문 전체가 등록 차원·별칭과 집계 실행어로 해석될 때 공통 차원 해석기를 먼저 호출한다. 업무별 허용 차원·날짜 역할과 식별 키는 원본 메타데이터에서 얻는다. 검색어에 집계 또는 별이 포함될 수 있으므로 문자열 치환으로 집계 질문을 만들지 않는다. 차원 이외의 조건이 남으면 기존 조건 해석 및 검증을 거친다. 미등록 차원을 유사한 이름으로 자동 교정하지 않는다.

업무마다 모든 등록 차원과 별칭에서 조사 유무·띄어쓰기·합계 표현을 생성한다. 표현별 그룹 키, 그룹 수, 원본 건수와 정확 금액을 독립 기댓값과 비교한다. 검색·검색 후 집계·다중 집계·오타를 반례로 포함하고, 원본 선택부터 채팅 게시까지는 별도 통합 검사한다. 단위 테스트 메서드 수와 실제 검증 질문 수를 구분한다.

### 원천 집계 계약

게시할 집계 표와 다음 현재표가 사용할 상세 원본의 키를 구분한다. 후보 판별은 DB를 호출하지 않으며 조회 전에 조건 전체를 검증한다. 명칭 안의 업무명, 인용문과 설명 질문을 음성 시험에 포함한다. 원천 호출·게시·후속 조회 횟수, 권한 회수, 방 복원을 각각 검증한다. 감사에는 적용된 조건 역할과 기간을 남기되 민감한 조건값 자체는 복제하지 않는다.

### 채팅 제출과 회사별 스키마 검증

기간을 해석하는 코드와 무라벨 검색어를 만드는 코드는 동일한 기간 구절 전체를 사용해야 한다. 복합 기간의 일부가 명칭 OR 검색에 들어가면 오류 없이 잘못된 결과를 낼 수 있다. 상대 기간과 동등한 절대 기간에 대해 날짜 열·바인딩·나머지 명칭 조건·행 식별자·게시 횟수를 대조하고, 날짜처럼 보이는 실제 업무명과 따옴표로 지정한 값도 음성 시험에 포함한다.

- 기간은 공통 기간 문법과 계산기를 호출한다. 업무별 기본기간·선택 날짜 역할은 화면과 서비스의 최종 바인딩을 따른다. 날짜처럼 보이는 명칭을 기간으로 소비하거나 잔여 조건을 버리지 않는다.
- 후보 판별만 통과한 사례를 실행 합격으로 세지 않는다. 실제 채팅 제출 블록에서 일반·웹·기존 ERP 경계, 호출 횟수, SQL 바인딩, 최종 카드와 원본 연결까지 대조한다. 현재 마스터 담당자와 거래 당시 담당자가 다른 자료를 검색·집계·내보내기 검증에 사용한다.
- 회사별 선택 열 차이는 실제 가시성을 확인하고 승인된 보조 열만 동일 타입의 NULL로 제공한다. 필수 열 누락은 오류다. 회사번호 분기, 필터 삭제, 오류 후 자동 재시도는 금지한다. 완성된 DataFrame 대역 시험과 물리 스키마/커서 시험 및 승인된 실조회 증거를 분리한다.
