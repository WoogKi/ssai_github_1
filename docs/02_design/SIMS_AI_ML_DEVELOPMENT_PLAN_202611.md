# ML 출고수요·발주 최적화 개발계획

**지위:** [공식 로드맵 v2.5](../00_roadmap/SIMS_AI_PLATFORM_MASTER_ROADMAP_v2.5_20261027.md)의 Phase 5 공식 개발계획. 본 계획 승인은 학습 데이터 접근·모델 운영 채택·배포 승인이 아니다. 기존 [발주계산 1차 업무 계약](ORDER_CALCULATION_PHASE1_BUSINESS_CONTRACT.md)은 변경하지 않는다. 기존 규칙 예측·발주 구현과 학습형 ML 미구현을 구분한다.

## 1. 첫 목표와 자료 계약 (P5-01~04, P45-08)

- 첫 타깃은 **제품·회사·예측 기준일별 향후 30일 정상 출고수량**이다. 출고반품, 취소·중복, 미결·장부 거래의 포함 여부는 현재 saved-I/O 및 원천 정책을 대조해 명시한다. **매출금액은 별도 타깃**으로 계산하고 금액 예측을 수량 대용으로 사용하지 않는다.
- 후보 원천은 R120 출고상세와 승인 Analytics/Snapshot 월별 근거, R110 입고, R210/R220 재고·출고 집계, 발주/미입고, 제품·거래처·제약사·매입처·재고위치·단가/재고적용처다. 원천마다 집계 단위, 유효 기간, 반품 부호, 회사·Profile, 마지막 승인 Generation을 기록한다. R210/R220의 의미 차이와 미결 매출 정책은 미결정으로 남긴다.
- 제품별 출고수량/빈도, 거래처·제약사 매출실적, 입고·재고 이력, 발주·미입고, 월·요일·계절성을 feature 후보로 두되 **기준일 당시 알고 있던 값만** 사용한다. 추후 확정금액, 미래 입고, 사후 수정된 등급이나 전체 기간 통계가 과거 학습행에 섞이지 않도록 as-of join과 데이터 버전/수정시각을 검증한다. 적격 시점 근거가 없으면 해당 feature는 제외한다.
- 학습셋은 회사/제품 코드 문자열과 앞자리 0, 품목 생애주기, 미출고·단종·신제품, 결측/0수요를 보존한다. 회사 간 자료 통합은 권한 및 학습 목적 승인 전 금지한다. 전체 조회와 표시 샘플을 구분한다.

## 2. 모델·검증 (P5-05~07)

| 단계 | 구현·비교 범위 | 운영 채택 경계 |
| --- | --- | --- |
| 기준선 | 현재 규칙 기반 수량 예측, 단순 이동평균, EWMA | 동일 원천·시점·horizon에서 산출. 데이터 부족 시 현행 규칙 유지 |
| 학습 후보 | Random Forest, XGBoost **또는** LightGBM | 복잡도/설치·추론시간·설명력 비교 후 한 후보 선택. 딥러닝은 1차 제외 |
| 수요 구분 | 자주 출고·간헐 출고 제품을 빈도/0수요 비율로 사전 정의 | 빈도 기준을 검증 구간을 보고 맞추지 않음. 간헐 수요의 0예측 편향 점검 |
| 평가 | 여러 과거 기준일의 순차 학습·검증, 향후 30일 실제 출고와 비교 | 시간순 holdout, 회사·제품군·등급별 WAPE/편향 및 과소·과대예측 분포. 0분모 WAPE 처리 명시 |
| 업무 효과 | 재고부족·과잉재고·권장 발주량 변화 | 당시 알 수 있던 재고/미입고와 대조한 Shadow 평가; 인과 개선이라고 단정하지 않음 |

### 과거월 반복 백테스트와 최종 평가

1. 충분한 과거 자료가 확보된 회사에서 여러 과거 **월말 기준일**을 시간순으로 정한다. 기준일마다 당시 알 수 있던 승인 원천·제품 Universe·재고/미입고만 다시 구성하고, 다음 날부터 **연속 30일**의 제품별 정상 출고수량을 예측한다. 이 기간은 달력상 익월 전체와 다를 수 있으므로 익월 예측을 별도 지표로 둔다.
2. 각 기준일의 30일이 끝난 뒤 확정된 실제 정상 출고량과 예측량을 동일 회사·제품·기간·단위로 대조한다. 고정한 기존 규칙 모델과 이동평균/EWMA/트리 후보를 같은 기준일에 실행한다. 실적이 아직 확정되지 않았으면 정확도 판정을 보류한다.
3. 월별·제품별·출고빈도별·회사별 WAPE와 부호 있는 편향, 과소·과대예측 및 0수요 구간을 비교한다. WAPE의 분모가 0인 구간은 별도 건수/절대오차로 보고하며 임의로 0점 처리하지 않는다. 출고가 잦은 제품과 간헐 출고 제품의 합격 여부를 따로 본다.
4. 다음 과거월로 이동하면서 **학습·모델 선택용 과거 구간**에서만 학습 기간·Feature·모델을 수정한다. 각 단계의 학습 데이터 종료시각과 label 가용시각을 기록하고, 시계열 fold 사이의 미래 실적/사후 등급 유입을 차단한다.
5. 마지막 **최종 평가 기간은 사전에 잠그고** 모델/Feature/하이퍼파라미터 선택에 쓰지 않는다. 최종 결과를 보고 조건을 바꾸면 새 최종 평가 기간을 마련해야 한다. 회사 간 전이 평가는 회사별 승인과 격리 기준을 따로 적용한다.

R120 등 원천의 소급 정정과 Snapshot/Fact 재생성 이력으로 과거 기준일 당시 값을 복원할 수 있는지 확인한다. 시점별 이력·원천 수정시각이 없어 재현할 수 없는 항목은 학습 feature에서 제외하거나 **사후 자료를 이용한 근사 백테스트**로 범위를 표시하며, 이를 누수 없는 최종 평가로 주장하지 않는다. 관측 출고량이 재고소진으로 제한된 구간도 실제 수요와 혼동하지 않는다.

평가 데이터, 최소 표본 수, 허용 WAPE·편향·stockout/과잉 위험 임계값은 업무 책임자에게 제안·승인받는다. 데이터 부족 제품은 현행 규칙 기반으로 유지하고, 동일 조건의 고정 기준선을 개선하지 못한 ML은 운영에 넣지 않는다. 임계값을 시험 결과에 맞춰 사후 완화하지 않는다.

## 3. 발주 연계 (P5-08~12)

ML 예상수요와 기존 예상수요를 원천·기준일·단위·범위가 보이는 별도 값으로 저장/표시한다. 기존 [수량·안전/적정재고·미입고·발주단위 계약](ORDER_CALCULATION_PHASE1_BUSINESS_CONTRACT.md)은 그대로 두고, 동일 조건에서 기존 권장 발주량과 **ML 기반 가상 권장 발주량**을 Shadow 비교한다. 발주권장량 차이의 원인을 수요 입력 차이와 기존 반올림/단위 차이로 나눠 기록한다. ERP 발주 전표 자동 등록은 이 범위에서 제외한다.

확장 순서는 매출금액 예측, 제약사·거래처별 예측, 재고부족/과잉 위험, 발주 최적화 순으로 검토한다. 거래처 수금·지급 예측은 [ERP 장부·잔액 계약](SIMS_AI_ERP_LEDGER_BALANCE_PLAN_202611.md)이 확인된 뒤 별도 타깃·권한·평가 기준을 마련한다.

## 4. 단계와 Gate

1. 11/1~7: 월마감 안정 후 원천·시점·취소/반품·회사 승인 범위·30일 타깃 정의, 과거월/최종 평가 구간 분리, 데이터 누수 Gate. 전방 검증용 예측을 발행할 수 있으면 기준일과 모델 버전을 고정한다.
2. 11/9~20: 승인된 범위의 충분한 과거월로 반복 백테스트. 규칙/통계/트리 모델을 동일 시점에 비교하고 학습용 구간에서만 개선한다. 운영 발주 경로는 미변경.
3. 11/23~30: 잠근 최종 과거 평가 기간의 회사/등급/간헐 수요 오차 보고; WAPE·편향·업무효과 임계값 승인 후보 제안. 최종 결과로 조건을 사후 조정하지 않는다.
4. 12월: 실제 발행 시점부터 30일이 경과하고 실적이 확정된 **전방 검증**과, 기준선 개선이 확인된 모델의 발주 Shadow 평가를 구분한다. 권한·성능·재현성·모델 버전 및 rollback Gate 후 1호기 수동 시험; 2호기는 별도 승인. 실적 미확정이면 판정을 연기한다.

**미확인·위험:** 회사별 R120/R210/R220 원천 차이, 미결 거래, 사후 수정자료의 as-of 재현성, 품목별 희소성, 결측 및 재고소진에 의한 관측 출고량 검열. 이 계약을 확인하기 전 예측 정확도를 운영 성공으로 보고하지 않는다.
