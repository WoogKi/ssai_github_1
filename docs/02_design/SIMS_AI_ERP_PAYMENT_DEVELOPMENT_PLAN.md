# SIMS AI 입출금 관리 단계별 개발계획

2026-11-27 · 계획서, 실행 승인 아님. 정책과 호출 계약은 [통합 상세설계](SIMS_AI_ERP_PAYMENT_REDESIGN_20261127.md), 재사용·테스트 원칙은 [공식 ERP 개발 표준](SIMS_AI_ERP_FEATURE_DEVELOPMENT_STANDARD.md), 자연어 우선순위는 [NLQ 개발 정책](SIMS_NLQ_DEVELOPMENT_POLICY.md)에 따른다. 단계 번호는 업무 의존성을 나타내며 운영 DB 조회·배포를 포괄 승인하지 않는다.

## 마감 상태 (2026-11-27)

L2-1 기본 조회와 현재표는 1호기 사용자 최종 합격. Git 반영·배포는 별도 승인 후 수행한다. L2-2 원천 NLQ는 기존 전체 NLQ의 실제 라우팅·조건·서비스 호출을 조사하고 상세설계와 테스트 계획을 사용자와 확정한 뒤 통합 구현한다. 이번 마감에서 착수하지 않는다.

후속 순서: L2-2 NLQ → L2-3 연계·승인된 유효 상태 → L3 매출·매입원장 → L4 장부잔액 중심 잔액현황·실잔액 비교 → L5 회전일·금융 집계 → L6 통합 검증·배포. 기존 ERP의 다중 기준 집계 확대 및 LLM 분석·답변 품질 종합 개선은 별도 과제다.

## 2. R4 내부 작업순서

1. **기준 고정:** 기존 WIP와 L2-1 증분을 분리하고 action·메뉴·payload 키·호출자 목록을 만든다. R110의 조건부 전체자료 선택 문제는 별도 개선 목록에 기록만 한다. 날짜 역할·고급조건·고정 열을 화면 시안과 대조한다.
2. **메타/안전 경계:** DDL 5종 PK·필드·타입/라벨·코드그룹 표 대조 → 공통 SCHEMA/LABELS 투영. 데이터가 승인된 회사 외부로 나가거나 기본 연결로 우회하지 않도록 조회/소비자에 같은 scope 검사. 정확 금액용 reader와 XLSX/분석 경로는 기존 기본값을 바꾸지 않는 선택 계약으로 먼저 검증한다.
3. **원본 서비스:** 3개 업무 SELECT와 정규 조건·안정 정렬, 명칭 JOIN 무증식, 초과 거부를 검증. full 확보 후 display만 파생한다. 260/270 메타를 사용하기 위해 의미 없는 서비스를 만들지 않는다.
4. **UI와 결과:** 최근 한 달(달력 기준) 날짜와 역할별 후보 → 명시 제출 → 공통 결과 1회. 대화방·회사 변경 시 payload/현재표/내보내기 범위를 검증한다. 새 NLQ는 공개하지 않는다.
5. **전환 후 폐기:** 이전 finance 전용 모듈·modal/form·wrapper·렌더/권한 조기반환·월집계 등록·캐시·테스트 import를 제거. 과거 저장 메시지의 요약·만료 표시와 제품재고현황 키는 남긴다. 기존 정책 전체를 reset하지 않고 기능별 증분만 교체한다.
6. **검토 제출:** 원천→공통 소비자 호출 근거, 3개 업무 fixture, 권한 부정 사례, export 파일 왕복, 기존 ERP/KPIS 비교 결과를 정리한다. 실제 적용해 보지 않은 성능·브라우저 UX·회사별 원본 일치는 R5로 표시한다.

## 4. 승인 장부

- **확정:** 메뉴 ‘입출금 관리’의 위치, 직접 조회 3종, 일반 기본기간 최근 달력 한 달, 월집계 미노출, 장부 기본, IO_READ와 다운로드 추가 EXPORT_EXCEL, 유효자료와 일반조회 분리.
- **R4 검토:** 320/330 일반조회 기본 날짜 역할(등록일 우선 적용, R5 확인), 회수 관련 필드 라벨 및 사용 범위, 각 표의 우선순위/고정열, 승인할 분석 측정값. 역할 미확정은 무조건 전표일로 대체하지 않는다.
- **L2-3 이후 별도 합의:** 기준일 현재 결제·양도·분할·회수·재제공의 판정표, 이월·부호·32/82 원장 표시 옵션, 거래처 기준·영업/회계 범위, 실/장부 대사, 회전일·여신 공식. 각 단계는 표본·반례·기대 결과와 별도 승인 없이는 구현하지 않는다.

## R4 구현 인계 (당시 기록, R5 합격으로 종결)

직접 메뉴 3종과 공통 카드·다운로드·분석 연결을 구현했다. 260/270 직접 조회와 L2-1 전용 모듈 5개는 폐기했다. R5 수동 확인은 완료되었고 배포 검증과는 구분한다. 310 입출금일, 320/330 등록일 기본값, 월말·윤년 범위, 조건 변경 후 1회 제출, 표시행을 넘는 표의 전체 내보내기, 권한 없는 다운로드·회사 변경 후 접근 차단을 표본과 대조한다. L2-2 이상은 진행하지 않았다.

## R5 수동 검증 이력 (합격)

1차 입출금 표본에서 전체 다운로드·분석은 정상이었으나 패널과 카드의 표시 순서 및 표시 건수가 달랐다. 보정 후에는 세 업무 각각 첫 조회와 단순 rerun에서 카드가 조건보다 앞서는지, 완료 건수가 카드와 같은지, 명칭 조건 미일치 시 0건인지 확인한다. 전체자료와 회사 격리까지 재확인하고 사용자 승인 전 다음 단계로 진행하지 않는다.

## R5 현재표 연계 (1호기 최종 합격)

현재표 명칭·기간·금액 집계는 L2-R5에서 공통 handler로 연결했다. 1호기에서는 현재표 일자별→월별→금액 TOP 10을 연속 실행하여 원본 키 유지, 선택 기준일별 합계, 각 파생표의 다운로드·분석 근거 및 권한 회수를 확인한다. 신규 원천 NLQ, 원장, 유효상태는 별도 승인 전 미구현이다.

### R5 담당자 및 후속 결과 표시 보정

담당자 확인은 매입처·매출처 각각 현재 거래처관리의 영업사원과 비교하고, 원본 전표 담당자는 별도 확인한다. 명칭 LIKE와 동명이인, 음수·0·결측, 담당자별 입금·출금 순위를 검증한다. 일자·월별 합계 대조에는 미분류를 포함한다. 최초·TOP 표·다운로드의 날짜와 빈칸도 비교한다. 영숫자 정상 출금코드가 숫자 변환 때문에 미분류로 빠지던 문제는 문자형 비교로 수정했고 1호기에서 합격했다.
