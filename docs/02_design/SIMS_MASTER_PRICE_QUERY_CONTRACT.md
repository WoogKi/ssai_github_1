## 마스터 조건과 회사격리

제품코드·보험코드와 거래처 코드는 문자열로 보존한다. 바코드는 기존 1~5 필드의
정확 일치 조건, 제품 키워드는 기존 제품명/제품코드/보험코드 검색 계약을 따른다.
그룹·구분·분류 코드명은 코드마스터의 그룹코드와 세부코드를 함께 사용한다.
`product_only_use` 조건을 켰을 때 제품 `Rd04_Use_Gu='0'` 조건을 사용한다.
모든 조회에 사용제품 필터가 기본 적용된다고 가정하지 않는다.

거래처 활성 조회는 기존 삭제표시 제외 조건을 따른다. 제조사·매입처·판매처 등
역할별 코드 범위를 유지한다. 단가적용처와 재고적용처의 후보 코드 범위가 같아도
업무 의미는 독립적이다. 이름 충돌·복수 후보는 기존 확인 경로를 사용한다.
회사 전환 시 이전 회사의 코드명·현재표·다운로드 캐시를 재사용하지 않는다.
대표매입처는 Snapshot/발주에서 사용하는 기존 선정 기준을 재사용하며,
제품 마스터의 발주처나 매입처 필드로 임의 대체하지 않는다.

## R070 최종 계약단가와 이력

현재 계약 조회는 단가적용처·제품별로 기준일 이하의 시작일을 가진 계약 중
시작일 내림차순 첫 행을 선택한다. 이력 조회는 계약 시작일 범위의 행을 조회한다.
현재 계약 조회의 선택 후 시작일 범위 필터와 기준일 유효성은 구분한다.
유효성은 현재 코드의 시작일 기준이며 구현되지 않은 종료일 판정을 추가로 설명하지 않는다.
기존 선택 helper의 빈 적용처·무효 시작일·삭제 E·가격 전부 0 제외 계약을 보존한다.
실/장부/일반 매입·매출 가격 필드는 서로 대체 가능한 하나의 단가가 아니다.

동일 적용처·제품·최신 시작일이 중복이면 현재 정렬에는 추가 동률 해소 기준이 없다.
따라서 이 문서는 그 경우 유일한 가격이 보장된다고 주장하지 않는다.
발주 계산은 일반 NLQ 기간을 계약 시작일 조회 필터로 넘기지 않는다.
관련 [발주 가격 계약](ORDER_CALCULATION_PHASE1_BUSINESS_CONTRACT.md)과
[기간정책](SIMS_AI_NLQ_기간정책_공식기준.md)을 따른다.

## R230 구매원가·최종매입가 조회의 의미

'최종 매입단가 조회'는 현재 원가·재고 상태 행 조회이다. 시간순 최신 매입전표를
한 제품당 하나 선정하는 조회가 아니다. 복수 거래처·위치·적용처·원가 행은 정상 단위다.
재고수량은 입고수량-출고수량, 실/장부 재고금액은 해당 재고수량×각 원가다.
제품 추가/수정 등 이 조회에서 지원하지 않는 조건은 서비스 정규화 계약을 따른다.
날짜 없는 상태 행을 거래일자 최신 가격이라고 해석하지 않는다.
발주 가격 fallback에서 복수 후보를 임의 선택하거나 평균가를 생성하지 않는다.
제품재고장의 거래 이력 기반 최종매입가와 R230 상태 조회를 혼동하지 않는다.
