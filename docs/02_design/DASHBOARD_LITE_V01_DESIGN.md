# SIMS AI Dashboard 설계안

**작성일:** 2026-07-22
**상태:** 검토용 설계 기준(v0.2)
**연계 문서:** `DASHBOARD_KPI_NLQ_공통조회조건_확정안_ver03.md`

## 1. 목적

Dashboard는 긴 표를 먼저 보여주는 화면이 아니다. 사용자가 현재의 매출·매입·재고 상태를 빠르게 보고, **오늘 무엇을 확인하고 조치할지** 결정하도록 돕는 첫 화면이다.

화면의 고정 순서는 다음과 같다.

```text
상태 → 근거 → 조치 → 상세표
```

- 상태: 핵심 카드와 그래프로 정상·주의·위험을 한눈에 보여 준다.
- 근거: 금액·수량·비율·추세와 비교 기준을 함께 보여 준다.
- 조치: 우선순위가 높은 5~10개만 제시한다.
- 상세표: 기존 KPI·SIMS 조회표로 이동하여 원인을 확인한다.

Dashboard는 기존 상세 조회를 대체하지 않는다. 공통 기초집계와 기존 KPI 서비스를 재사용하여, 같은 숫자를 서로 다르게 계산하지 않게 한다.

| 재고 | 실재고/장부재고 선택, 준비율, 부족·과잉·저활성, 재고회전일 | 경보 이력·반복 알림 억제 |

## 3. 날짜 정책

| 조건 | 역할 | 평가월이 202607일 때 기본값 |
|---|---|---|
| 시작월 | 평균·추세·계절성 판단을 위한 과거 자료 시작 | 202601 |
| 종료월 | 완료월 실적을 집계하는 마지막 월 | 202606 |
| 평가월 | 재고·당월실적·예상·진척률을 판단하는 기준월 | 202607 |

- 기본값은 `시작월=평가월-6개월`, `종료월=평가월-1개월`, `평가월=당월`이다.
- `202501 / 202507 / 202607`처럼 전년 동기간을 기준으로 현재 평가가 가능하다.
- `202506 / 202606 / 202607`처럼 최근 13개월을 선택하여 계절 품목도 함께 판단할 수 있다.
- 화면·Excel의 표시 범위가 `202601~202606`이면, 내부적으로는 `202510~202606`까지 추가 조회하여 시작월부터 최근 3개월 추세를 계산한다. 이 보조 3개월은 완료월 평균·합계·건수·표시 범위에 넣지 않는다.
- 평가월이 진행 중이면 완료월과 직접 비교하지 않는다. 평가월은 `현재값`, `월말 예상`, `진척률`로만 해석한다.

### 4.1 날짜와 추가 분석조건

날짜 줄은 항상 표시하고, 그 아래의 `추가 분석조건`은 기본 접힘으로 둔다. 접혀 있어도 현재 적용값과 Default 여부를 요약해 보여 준다.

추가 분석조건의 전체 구성은 연계 문서 3장을 따른다.

| 구분 | 조건 | 방식 |
|---|---|---|
| 재고 | 재고기준, 재고위치 | 재고기준 단일 / 위치 복수 선택 |
| 거래처 | 거래처그룹, 거래처종류 | 복수 선택 |
| 제품 | 제품그룹, 제품구분, 제품분류 | 복수 선택 |
| 입출고 | 입출고구분 | 복수 선택 |
| 분석 기준 | 대표 매입처 기준기간, 위험 분석기간, 과잉·저활성 기준, 준비율 경고기준, 위험품목 바로보기 기준 | 숫자 입력 |
| 표시 | 금액 표시 단위 | 자동 / 원 / 천원 / 백만원 |

- 입출고구분 `0·1·5·6`은 `입출고구분 코드의 첫 자리`다. 각각 입고·입고반품·출고·출고반품을 의미한다.
- 관리용·금융할인·조정·사은품을 포함한 모든 제품은 자동 제외하지 않는다. 사용자가 제품그룹·제품구분·제품분류 복수 선택으로 분석 범위를 직접 정하며, 금융할인 제품그룹(`0013:A001`)도 필요할 때만 선택해 제외하거나 포함한다.
- 화면·그래프·AI 요약에는 선택한 금액 단위를 적용한다. Excel은 언제나 원본 숫자(원 단위)를 유지한다.

### 4.2 저장·Default·권한

- 저장은 **접힌 추가 분석조건 영역 안에서만** 제공한다. `[저장조건 목록/불러오기]`는 제공하지 않으며, 회사별 현재 Default 조건 하나를 저장·갱신한다.
- 저장된 회사 기본 프로필은 접힌 제목 줄에 `Default: 프로필명`으로 표시한다.
- 회원사 관리자와 신성 관리자만 위 저장 기능을 사용할 수 있다.
- 해당 화면 조회 권한을 가진 모든 사용자는 Default 조건을 초기값으로 받고, 임시로 조건을 바꿔 조회할 수 있다.
- 일반 사용자는 저장·수정을 할 수 없다.

프로필 저장은 SSAI 관리 DB의 `SSAI_ANALYSIS_PROFILES`와 `ANALYSIS_PROFILE_MANAGE` 권한으로 구현한다. 날짜는 저장하지 않고, 회사별 활성 Default는 하나만 허용한다. Dashboard·KPI·NLQ는 동일 Default를 초기값으로 사용하며, NLQ에서 사용자가 명시한 조건이 최종 우선한다.

## 5. 핵심 카드와 차트

### 5.1 오늘의 업무 브리핑

첫 줄에는 숫자 나열보다 판단을 보여 준다.

| 표시 | 내용 |
|---|---|
| 전체 상태 | 정상 / 주의 / 위험 중 가장 높은 상태 |
| 위험·주의 건수 | 오늘의 조치 대상 수와 영역별 건수 |
| 가장 먼저 확인할 일 | 부족금액·고매출 감소·입고지연 중 우선순위 1건 |
| 기준 | 적용 기간, 재고기준, 주요 임계값 |

예: `위험: 재고부족 7건. 부족금액이 가장 큰 A제품의 대표 매입처 입고지연을 먼저 확인하세요.`

### 5.2 매출 영역

| 구성 | 표시·계산 기준 | 상세 연결 |
|---|---|---|
| 완료월 매출 추세 | 시작월~종료월 월별 매출. 시작월부터 추세 계산 | 제약사별/품목별 매출 추세 |
| 평가월 현재매출 | 평가월 현재 누계 | 매출 예상 상세 |
| 평가월 예상매출 | 기존 예측 서비스의 월말 예상 | 매출 예상 상세 |
| 평가월 진척률 | 현재매출 ÷ 예상매출 | 매출 예상 상세 |
| 감소 위험 | 매출 상위이면서 감소 판정 또는 감소 기여가 큰 대상 | 제약사별/품목별 추세 |

차트는 완료월 실선, 평가월 현재 marker, 평가월 예상 점선으로 표시한다. 진행 중인 평가월에는 `진행 중`을 명시한다.

### 5.3 매입 영역

| 구성 | 표시·계산 기준 | 상세 연결 |
|---|---|---|
| 입고 추세 | 선택한 입출고구분과 제품·거래처 조건을 적용한 월별 입고 | 입고명세/매입처별 재고부족 |
| 대표 매입처 | 최근 입력 기준기간의 정상 입고수량이 가장 큰 실제 매입처 | 매입처별 재고부족 |
| 최근 입고 경과일 | 평가 기준일 - 마지막 정상 입고일 | 입고명세 |
| 매입 거래 회전일 | 정상 입고 고유 거래일 간 평균 일수 | 입고명세 |
| 입고 지연 후보 | 최근 경과일이 회전일 대비 기준을 초과하고 수요·재고 위험이 있는 대상 | 품목별 재고부족 |

정상 입고일은 `Rddbc110.Rd11_In_YyMmDd`를 우선 사용한다. 같은 날 여러 명세서는 한 거래일로 본다. 반품은 별도 표시하고 정상 거래 회전일에는 포함하지 않는다. 거래일이 0~1개면 `자료부족`으로 표시하고 위험으로 단정하지 않는다.

### 5.4 재고 위험 영역

| 구성 | 표시·계산 기준 | 상태 |
|---|---|---|
| 재고기준 | 사용자가 선택한 실재고 / 장부재고 | 선택값 전체에 일관 적용 |
| 재고 준비율 | `min(max(현재재고, 0), 잔여예상수요) ÷ 잔여예상수요 × 100` | 입력 기준 미만 경고 |
| 부족수량·부족금액 | `max(잔여예상수요 - 현재재고, 0)` | 부족 발생 시 위험 후보 |
| 재고커버일 | 현재재고를 기간 수요로 환산한 일수 | 과잉·저활성 기준과 함께 해석 |
| 과잉·저활성 | 입력한 재고회전일 기준 초과 | 주의 또는 위험 후보 |
| 장부/실재고 차이 | 두 기준을 비교 조회한 경우에만 보조 지표 | 데이터 품질 예외 |

- 잔여예상수요가 0이면 준비율은 100%로 표시한다.
- 준비율은 화면 상한을 100%로 두며, 입력한 경고기준 이상은 일반 경고를 표시하지 않는다.
- 재고 0·음수, 핵심품목, 커버일 부족, 장부/실재고 불일치는 침묵정책보다 우선하여 표시한다.
- 재고값은 실재고 선택 시 `Rddbc210`, 장부재고 선택 시 `Rddbc220`을 사용한다.

## 6. 오늘의 조치 생성 규칙

오늘의 조치는 최대 10건이며, 동일 품목·동일 원인은 하나로 묶는다.

| 우선순위 | 후보 | 필수 근거 | 권장 상세표 |
|---:|---|---|---|
| 1 | 재고 부족 | 준비율, 부족수량 또는 부족금액, 대표 매입처 | 품목별 재고부족 |
| 2 | 고매출 감소 | 매출 순위와 감소금액 또는 감소율 | 제약사별/품목별 매출 추세 |
| 3 | 입고 지연 | 최근 입고 경과일, 회전일, 현재 재고·수요 | 입고명세 / 매입처별 재고부족 |
| 4 | 과잉·저활성 | 재고회전일, 재고금액, 최근 출고 | 품목별 재고부족 |
| 5 | 데이터 품질 | 재고 음수, 장부·실재고 차이, 자료부족 | 해당 원장/상세표 |

각 조치는 `상태 · 대상 · 근거값 · 기준 · 권장 조치 · drill-down 조건`을 가진다. LLM이 원시 표를 다시 계산하지 않고, 이 결정론적 facts를 설명만 하게 한다.

## 7. 데이터 원천과 적용 규칙

| 목적 | 원천 | 주요 필드/규칙 |
|---|---|---|
| 제품·제약사·발주처·분류 | `Rddbc040` | 제품코드, 제품그룹·구분·분류, 제약사, 발주처 `Rd04_Orven_Cd` |
| 입고 | `Rddbc110` | 입고일 `Rd11_In_YyMmDd`, 매입처, 재고위치, 제품, 입출고구분 |
| 출고 | `Rddbc120` | 출고일 `Rd12_Out_YyMmDd`, 매출처, 재고위치, 제품, 입출고구분 |
| 월 실재고 | `Rddbc210` | 제품, 재고위치, 년월, 매입처, 재고적용처, 입출고구분 |
| 월 장부재고 | `Rddbc220` | 제품, 재고위치, 년월, 매입처, 재고적용처, 입출고구분 |
| 코드명 | `Rddbc010` | 그룹코드·상세코드에 대한 명칭 |

대표 매입처는 입력한 기준기간의 정상 입고수량이 가장 큰 실제 매입처로 정하며, 기간 내 입고가 없을 때만 제품마스터 발주처로 보완한다.

모든 조건값은 명칭이 아니라 코드로 저장·전달한다. 입출고구분·제품분류 등 코드 조건은 입고·출고·재고 원천 모두에 같은 의미로 적용되는지 구현 전 회귀 데이터로 확인한다.

## 8. 화면 동작·성능 원칙

- 조회 버튼을 누를 때 공통 기초집계(facts)를 한 번 생성하고, 카드·그래프·조치목록은 그 facts를 재사용한다.
- 같은 조건에서 카드 접기·펼치기, 표시단위 전환, 상세조치 선택은 DB 재조회 없이 처리한다.
- 기간·재고기준·필터·임계값이 바뀔 때만 facts를 다시 생성한다.
- 최초 조회 목표는 운영 DB 기준 약 18초 이내로 관리하고, 동일 결과의 화면 조작은 1초 내외를 목표로 한다.
- 결과에는 적용 조건, 데이터 기준일, 자료부족 여부를 항상 남긴다.

## 9. 구현 순서와 완료 기준

1. **기준 데이터 확정**
   - 재고금액의 평가단가 기준과 장부/실재고 집계 검증 방법을 확정한다.
2. **날짜·공통 조건 UI**
   - 기본 날짜, 내부 3개월 추세, 접기/펼치기, 복수선택·숫자입력·표시단위를 구현한다.
3. **권한·프로필 저장**
   - `SSAI_ANALYSIS_PROFILES`, `ANALYSIS_PROFILE_MANAGE`, 관리자 전용 저장·목록·Default를 구현한다.
4. **공통 facts와 Dashboard 화면**
   - 매출·매입·재고 facts를 공통 조건으로 만들고 카드·차트·조치목록에 연결한다.
5. **KPI·NLQ 기본조건 연결**
   - 동일 Default를 초기값으로 사용하고, NLQ 명시조건 우선 규칙을 적용한다.
6. **회귀·운영 검증**
   - 기존 KPI/NLQ 회귀, 권한, 실재고/장부재고, 복수선택, Excel 원본단위를 검증한다.

### 단계별 필수 합격 기준

- 복수 선택한 거래처·제품·입출고구분이 SQL과 결과 요약에 정확히 반영된다.
- 실재고/장부재고 선택이 재고수량·금액·준비율·위험 판정에 일관되게 적용된다.
- 비관리자는 저장·프로필 목록을 볼 수 없고, 정상 사용자는 임시 조건 조회가 가능하다.
- Default가 Dashboard·KPI·NLQ의 초기값에 동일하게 적용된다.
- 시작월 첫 달부터 최근 3개월 추세가 계산되며, 보조 3개월이 완료월 평균·합계에 섞이지 않는다.
- Excel은 표시단위와 무관하게 원본 원 단위를 유지한다.
