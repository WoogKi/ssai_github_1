## 1. 목적

Dashboard는 긴 표를 먼저 보여주는 화면이 아니다. 사용자가 현재의 매출·매입·재고 상태를 빠르게 보고, **오늘 무엇을 확인하고 조치할지** 결정하도록 돕는 첫 화면이다.

화면의 고정 순서는 다음과 같다.

```text
상태 → 근거 → 조치 → 상세표
```

- **상태:** 핵심 카드와 그래프로 정상·주의·위험을 한눈에 보여 준다.
- **근거:** 금액·수량·비율·추세와 비교 기준을 함께 보여 준다.
- **조치:** 우선순위가 높은 항목을 최대 10건까지 제시한다.
- **상세표:** 기존 KPI·SIMS 조회 화면으로 이동하여 원인을 확인한다.

Dashboard는 기존 상세 조회를 대체하지 않는다. 공통 기초집계와 기존 KPI 서비스를 재사용하여 같은 숫자를 서로 다르게 계산하지 않게 한다. LLM은 결정론적으로 생성된 facts를 다시 계산하지 않고 설명과 요약만 담당한다.

## 3. 날짜와 평가월 정책

| 조건 | 역할 | 평가월이 202607일 때 기본값 |
|---|---|---|
| 시작월 | 평균·추세·계절성 판단을 위한 과거 자료 시작 | 202601 |
| 종료월 | 완료월 실적을 집계하는 마지막 월 | 202606 |
| 평가월 | 재고·당월실적·예상·진척률을 판단하는 기준월 | 202607 |

- 기본값은 `시작월=평가월-6개월`, `종료월=평가월-1개월`, `평가월=당월`이다.
- `202501 / 202507 / 202607`처럼 전년 동기간을 기준으로 현재를 평가할 수 있다.
- `202506 / 202606 / 202607`처럼 최근 13개월을 선택하여 계절 품목을 함께 판단할 수 있다.
- 화면·Excel 표시 범위가 `202601~202606`이면 내부적으로는 `202510~202606`까지 추가 조회하여 시작월부터 최근 3개월 추세를 계산한다. 이 보조 3개월은 완료월 평균·합계·건수·표시 범위에 넣지 않는다.
- 진행 중인 평가월은 완료월과 직접 비교하지 않는다. 평가월은 `현재 실적`, `월말 예상`, `월 달성률`, `일자 기준 달성률`, `페이스 차이`로 해석한다.
- 일자 계산에는 시스템 현재시각을 무조건 사용하지 않는다. Dashboard facts의 **데이터 기준일** 또는 명시된 `policy/data cutoff date`를 사용한다.
- 일자 기준은 우선 달력일 기준으로 계산한다. 영업일 기준 계산은 별도 확장으로 둔다.

### 3.1 평가월 달성 지표

평가월이 현재 진행월일 때 다음을 계산한다.

```text
월 달성률
= 현재매출 ÷ 월말 예상매출 × 100

기간 경과율
= 평가월 경과일수 ÷ 평가월 전체 일수 × 100

오늘까지 기대매출
= 월말 예상매출 × 기간 경과율

일자 기준 달성률
= 현재매출 ÷ 오늘까지 기대매출 × 100

페이스 차이
= 현재매출 - 오늘까지 기대매출
```

표시 원칙:

- `월 달성률`은 월말 예상 대비 현재 누계의 진척도를 뜻한다.
- `일자 기준 달성률`은 데이터 기준일까지 기대한 실적 대비 현재 실적의 진행 속도를 뜻한다.
- 예: 월말 예상 300, 30일 중 20일 경과, 현재 실적 200이면 월 달성률은 66.7%, 일자 기준 달성률은 100.0%다.
- 월말 예상 또는 오늘까지 기대매출이 0 이하이면 해당 달성률을 억지로 계산하지 않고 `자료부족` 또는 `계산 제외`로 표시한다.
- 평가월이 완료월이면 일자 기준 달성률을 표시하지 않고 실제 대비 사전예상 오차를 표시한다.
- 평가월이 미래월이면 현재 실적·일자 기준 달성률을 표시하지 않는다.

### 4.1 날짜와 추가 분석조건

날짜 줄은 항상 표시하고, 그 아래 `추가 분석조건`은 기본 접힘으로 둔다. 접혀 있어도 현재 적용값과 Default 여부를 요약해 보여 준다.

추가 분석조건의 전체 구성은 연계 문서의 공통 조회조건을 따른다.

Dashboard NLQ의 조건 우선순위:

1. 질문에 명시된 기간·제약사·발주처·담당자 조건
2. 회사별 저장 profile
3. 조건별 안전한 기본값

- 기간 미지정 시 완료된 직전 6개월을 사용하고 명시기간이 있으면 이를 우선한다.
- 담당자만 명시하면 `supplier_mode=order_vendor`를 기본으로 사용한다.
- 제약사 또는 발주처가 명시되면 담당자-only 기본보다 명시 mode를 우선한다.
- resolver 성공 후 적용된 facts가 0건이면 `no_data`/tableless로 종료하고 0원·0% Dashboard를 렌더하지 않는다.

| 구분 | 조건 | 방식 |
|---|---|---|
| 재고 | 재고기준, 재고위치 | 재고기준 단일 / 위치 복수 선택 |
| 거래처 | 거래처그룹, 거래처종류 | 복수 선택 |
| 제품 | 제품그룹, 제품구분, 제품분류 | 복수 선택 |
| 입출고 | 입출고구분 | 복수 선택 |
| 분석 기준 | 대표 매입처 기준기간, 위험 분석기간, 과잉·저활성 기준, 준비율 경고기준, 위험품목 바로보기 기준 | 숫자 입력 |
| 표시 | 금액 표시 단위 | 자동 / 원 / 천원 / 백만원 |

입출고구분 적용 원칙:

- 업무 의미는 첫 자리 `0=입고`, `1=입고반품`, `5=출고`, `6=출고반품`으로 분류한다.
- 실제 저장·전달·필터링은 `Rddbc010` 그룹 `0012`의 **선택한 전체 Tcode 코드값**을 사용한다.
- 첫 자리만 저장하여 세부 입출고 코드를 잃지 않는다.

제품 분석 범위:

- 관리용·금융할인·조정·사은품을 포함한 모든 제품을 자동 제외하지 않는다.
- 사용자가 제품그룹·제품구분·제품분류 복수 선택으로 포함 범위를 직접 정한다.
- 금융할인 제품그룹 `0013:A001`도 선택 여부에 따라 포함하거나 제외한다.

금액 표시 단위:

- 선택한 `자동 / 원 / 천원 / 백만원` 단위를 Dashboard 카드, 차트 축, 차트 라벨, 툴팁, 업무 브리핑, 오늘의 조치 근거, 화면 상세표에 일관되게 적용한다.
- facts와 handoff payload의 금액 원본은 원 단위로 유지한다.
- Excel은 표시 단위와 관계없이 항상 원 단위 원본 숫자를 내보낸다.

### 4.2 Dashboard 전용 제약사 임시조건

- 제약사 입력은 Dashboard 현재 조회를 위한 임시 텍스트 조건이다.
- 빈 값 또는 `전체`는 전체 범위로 처리한다.
- 코드 정확 일치를 우선하고, 미일치 시 제약사 한글명 포함 검색을 적용할 수 있다.
- 복수 후보는 현재 조회 범위의 코드 목록으로 확정하여 facts와 drill-down에만 전달한다.
- 제약사 임시조건은 회사 Default 저장 대상이 아니며 KPI·NLQ 공통 초기값으로 저장하지 않는다.
- 재로그인, 회사 전환, 새 세션에서는 `전체`로 초기화한다.

### 4.3 저장·Default·권한

- 저장은 **접힌 추가 분석조건 영역 안에서만** 제공한다.
- `[저장조건 목록/불러오기]`는 제공하지 않는다.
- 회사별 활성 Default 조건은 하나만 허용하며 관리자 저장 시 기존 Default를 갱신한다.
- 날짜와 Dashboard 전용 제약사 임시조건은 저장하지 않는다.
- 회원사 관리자와 신성 관리자만 Default 저장·갱신 기능을 사용할 수 있다.
- 해당 화면 조회 권한을 가진 모든 사용자는 Default 조건을 초기값으로 받고 임시로 조건을 바꿔 조회할 수 있다.
- 일반 사용자는 저장·수정을 할 수 없다.
- Dashboard·KPI·NLQ는 동일 회사의 Default를 초기값으로 사용하며 NLQ에서 사용자가 명시한 조건이 최종 우선한다.
- 물리 테이블·컬럼 명세는 실제 SSAI 관리 DB의 회사별 단일 Default 저장 구조와 일치하도록 관리하고, 기능 계약보다 오래된 예시 schema를 우선하지 않는다.

## 5. 핵심 카드와 시각화

### 5.1 오늘의 업무 브리핑

첫 영역에는 숫자 나열보다 판단을 보여 준다.

| 표시 | 내용 |
|---|---|
| 전체 상태 | 정상 / 주의 / 위험 중 가장 높은 상태 |
| 위험·주의 건수 | 오늘의 조치 대상 수와 영역별 건수 |
| 가장 먼저 확인할 일 | 부족금액·고매출 감소·입고지연 중 우선순위 1건 |
| 주요 근거 | 금액·수량·비율·경과일 등 결정론적 facts |
| 권장 조치 | 사용자가 바로 실행할 업무 문장 |
| 기준 | 적용 기간, 데이터 기준일, 재고기준, 주요 임계값 |

예:

```text
위험: 긴급 재고부족 7건입니다.
부족금액이 가장 큰 A제품의 대표 매입처와 입고 상태를 먼저 확인하세요.
기준: 실재고 / 데이터 기준일 2026-07-20 / 준비율 경고 {현재 profile 값}%
```

브리핑 문장은 LLM이 원시표를 다시 계산하여 만들지 않는다. 우선순위가 확정된 facts를 바탕으로 템플릿 또는 LLM 설명을 생성한다.

### 5.2 핵심 요약 카드

- 상단 핵심 카드는 4~6개 수준으로 제한한다.
- 카드 수를 늘려 상세 지표를 모두 나열하지 않는다.
- 권장 후보:
  - 현재매출
  - 월말 예상매출
  - 월 달성률
  - 일자 기준 달성률
  - 긴급 위험 SKU
  - 부족금액
  - 과잉·저활성 SKU
- 화면 폭과 업무 우선순위에 따라 위 후보 중 4~6개를 선택한다.
- 세부 근거는 차트·업무목록·상세표로 내린다.

### 5.3 매출 영역

| 구성 | 표시·계산 기준 | 상세 연결 |
|---|---|---|
| 완료월 실적 | 시작월~종료월 월별 실제매출 | 제약사별/품목별 매출 추세 |
| 완료월 사전예상 | 해당 월이 진행 중일 때 계산했던 당시 예상 | 품목별 매출 예상 |
| 평가월 현재매출 | 데이터 기준일까지의 평가월 현재 누계 | 매출 예상 상세 |
| 평가월 월말예상 | 기존 예측 서비스의 평가월 월말 예상 | 매출 예상 상세 |
| 월 달성률 | 현재매출 ÷ 월말예상 | 매출 예상 상세 |
| 오늘까지 기대매출 | 월말예상 × 기간 경과율 | 매출 예상 상세 |
| 일자 기준 달성률 | 현재매출 ÷ 오늘까지 기대매출 | 매출 예상 상세 |
| 완료월 예상오차 | 실제매출과 당시 사전예상의 금액·비율 차이 | 품목별/제약사별 추세 |
| 감소 위험 | 매출 상위이면서 감소 판정 또는 감소 기여가 큰 대상 | 제약사별/품목별 추세 |

매출 차트 최종 표현:

- 선/marker/점선 방식으로 전면 변경하지 않고 **막대 비교형을 유지**한다.
- 범례의 의미는 가능한 한 `실적 / 예상` 두 범주로 단순화한다.
- 완료월은 `실제매출`과 `당시 사전예상`을 월별 그룹 막대로 비교한다.
- 평가월은 `현재매출`과 `월말예상`을 그룹 막대로 비교한다.
- 평가월에는 `오늘까지 기대매출`을 얇은 기준표식 또는 직접 라벨로 추가한다.
- 평가월 축 라벨 또는 설명에 `진행 중`과 데이터 기준일을 표시한다.
- 완료월에는 실제 대비 사전예상 오차율을 툴팁 또는 보조 라벨로 제공한다.
- 막대가 서로 완전히 가려지지 않게 하며 값 비교가 우선되도록 한다.
- Y축, 라벨, 툴팁의 금액은 공통조건의 금액 표시 단위를 사용한다.
- 월 수가 적을 때는 월 라벨을 가로로 표시하고, 연도가 바뀌는 구간은 `YYYY-MM`로 명확히 표시한다.

평가월 상태 문구:

- 일자 기준 달성률이 100% 이상이면 `오늘 기준 앞섬` 또는 `정상 이상 페이스`
- 100% 미만이면 `오늘 기준 미달`
- 세부 경고 구간은 운영 데이터 확인 후 별도 임계값으로 확정한다.

### 5.4 매입 영역

| 구성 | 표시·계산 기준 | 상세 연결 |
|---|---|---|
| 입고 추세 | 선택한 입출고구분과 제품·거래처 조건을 적용한 월별 정상입고 | 입고명세/매입처별 재고부족 |
| 대표 매입처 | 입력한 최근 기준일수 동안 정상 입고수량이 가장 큰 실제 매입처 | 매입처별 재고부족 |
| 최근 입고 경과일 | 데이터 기준일 - 마지막 정상 입고일 | 입고명세 |
| 매입 거래 회전일 | 정상 입고 고유 거래일 간 평균 일수 | 입고명세 |
| 입고 지연 후보 | 최근 경과일이 회전일 대비 기준을 초과하고 수요·재고 위험이 있는 대상 | 품목별/매입처별 재고부족 |

정상 입고일은 `Rddbc110.Rd11_In_YyMmDd`를 우선 사용한다. 같은 날 여러 명세서는 한 거래일로 본다. 반품은 별도 표시하고 정상 거래 회전일에는 포함하지 않는다. 거래일이 0~1개면 `자료부족`으로 표시하고 위험으로 단정하지 않는다.

대표 매입처는 입력한 기준일수의 실제 정상 입고수량으로 산정한다. 기간 내 입고가 없을 때만 제품마스터 발주처 `Rddbc040.Rd04_Orven_Cd`로 보완한다. 월집계 6완료월 기준은 이전 구현 이력이며 최종 목표 기준은 일자 facts다.

### 5.5 재고 위험 영역

| 구성 | 표시·계산 기준 | 상태 |
|---|---|---|
| 재고기준 | 사용자가 선택한 실재고 / 장부재고 | 선택값 전체에 일관 적용 |
| 재고 준비율 | `min(max(현재재고, 0), 잔여예상수요) ÷ 잔여예상수요 × 100` | 입력 기준 미만 경고 |
| 부족수량·부족금액 | `max(잔여예상수요 - 현재재고, 0)` | 부족 발생 시 위험 후보 |
| 긴급·주의·정상 분포 | 위험 판정별 품목 수와 부족금액 | 분포 차트 |
| 재고커버일 | 현재재고를 기간 수요로 환산한 일수 | 과잉·저활성 기준과 함께 해석 |
| 과잉·저활성 | 입력한 재고회전일 기준 초과 | 주의 또는 위험 후보 |
| 수요급증 | 기존 예상보다 출고가 빠르거나 신규 수요가 확인된 품목 | 보조 위험 |
| 주요 매입처 위험 Top 10 | 대표 매입처별 위험 품목 수·부족금액 | 가로 막대 또는 누적 막대 |
| 장부/실재고 차이 | 두 기준을 비교 조회한 경우에만 보조 지표 | 데이터 품질 예외 |

- 잔여예상수요가 0이면 준비율은 100%로 표시한다.
- 준비율은 화면 상한을 100%로 두며 입력한 경고기준 이상은 일반 경고를 표시하지 않는다.
- 준비율 경고기준은 회사 profile 또는 현재 화면 설정값을 사용하며 문서 상수로 고정하지 않는다.
- 재고 0·음수, 핵심품목, 커버일 부족, 장부/실재고 불일치는 침묵정책보다 우선하여 표시한다.
- 재고값은 실재고 선택 시 `Rddbc210`, 장부재고 선택 시 `Rddbc220`을 사용한다.
- 현재 단일 재고기준 조회와 장부/실재고 동시 비교는 구분한다. 동시 비교는 별도 facts가 준비된 경우에만 표시한다.

## 6. 오늘의 조치와 상세 화면 연결

오늘의 조치는 최대 10건이며 동일 품목·동일 원인은 하나로 묶는다.

### 6.1 우선순위

| 우선순위 | 후보 | 필수 근거 | 권장 상세 화면 |
|---:|---|---|---|
| 1 | 긴급 재고 부족 | 준비율, 부족수량 또는 부족금액, 대표 매입처 | 품목별 재고부족현황 |
| 2 | 주의 재고 부족 | 준비율, 부족수량 또는 부족금액 | 품목별 재고부족현황 |
| 3 | 고매출 감소 | 매출 순위와 감소금액 또는 감소율 | 제약사별/품목별 매출 추세·예상 |
| 4 | 입고 지연 | 최근 입고 경과일, 회전일, 현재 재고·수요 | 입고명세 / 매입처별 재고부족 |
| 5 | 과잉·저활성 | 재고커버일, 재고금액, 최근 출고 | 품목별 재고부족현황 |
| 6 | 데이터 품질 | 재고 음수, 장부·실재고 차이, 코드 누락, 자료부족 | 해당 원장/상세 화면 |

입고 일자 facts가 없는 단계에서는 입고 지연 조치를 생성하지 않는다. 근거가 충분하지 않은 조치나 대상코드가 없는 조치에는 상세 버튼을 제공하지 않는다.

### 6.2 조치 facts 계약

각 조치는 최소한 다음 값을 가진다.

```text
action_id
priority
status
cause_type
target_kind
target_code
target_name
evidence_label
evidence_value
evidence_unit
threshold_label
threshold_value
recommended_action
drilldown_action
drilldown_params
source_dashboard_event_id
```

- `action_id`는 `원인유형 + 대상유형 + 대상코드`의 결정론적 조합으로 만든다.
- 현재시각, 무작위 UUID, 단순 행 번호만으로 식별하지 않는다.
- 금액 facts는 원 단위 원본을 유지하고 화면에서만 표시 단위를 적용한다.
- LLM은 원시표를 다시 계산하지 않고 이 facts를 설명만 한다.

### 6.3 화면 표현

오늘의 조치는 반복 카드가 아니라 행 단위 업무목록으로 표시한다.

```text
순위 | 상태 | 대상 | 핵심 근거 | 판정 기준 | 권장 조치 | 상세
```

- 첫 행에 열 제목을 표시한다.
- 최대 10행으로 제한한다.
- 상태·영향금액·비율·대상코드 순으로 안정 정렬한다.
- `판정 기준`에는 실제 facts의 임계값 또는 판정 근거만 표시한다.
- 최신 Dashboard primary 결과에서만 `상세 보기`를 활성화한다.
- 과거 Dashboard compact snapshot과 다른 방 복귀 결과는 읽기 전용으로 표시하며 버튼을 제공하지 않는다.

### 6.4 선택 조치 상세 계약

`상세 보기`는 최신 Dashboard primary 결과의 로컬 상호작용이다.

정상 흐름:

1. 현재 Dashboard의 조치 버튼 클릭
2. 현재 방·회사·Dashboard event·action·제품코드 선택 상태 저장
3. 현재 primary cache의 `risk_detail_rows`에서 제품코드 정확 일치 행을 검색
4. 오늘의 조치와 위험 품목 상세 사이에 선택 조치 상세 표시
5. 위험 품목 상세표를 같은 제품코드로 열고 검색값을 연결

- 상세 보기에는 DB 재조회, SIMS 패널 자동 실행, 채팅 push, handoff request, 명시적 `st.rerun()`을 사용하지 않는다.
- 반복 클릭은 동일 선택 상태만 유지하며, 다른 조치를 누르면 선택 상세를 교체한다.
- 방·회사·Dashboard event가 일치하지 않으면 선택 상태를 폐기한다.
- compact snapshot과 다른 방 복귀 결과는 읽기 전용이며 상세 버튼·선택 상세·위험 상세표·Excel을 제공하지 않는다.

### 6.5 선택 상세 데이터 기준

- 조치의 `target_code`와 `drilldown_params.product_code`는 실제 제품코드여야 한다.
- 주요매입처·제약사·제조사 코드는 제품코드 대체값으로 사용하지 않는다.
- 선택 상세는 `risk_detail_rows`에 실제 존재하는 컬럼만 표시하며, 없는 값은 계산하거나 추정하지 않는다.
- 위험 상세표의 로컬 필터와 토글은 기존 facts를 재사용하며 DB를 다시 조회하지 않는다.

## 7. 위험 품목 상세와 Excel

- 위험 품목 상세표는 현재 Dashboard primary 결과에서만 전체 기능을 제공한다.
- 상태, 대표 매입처, 수요급증, 제품 검색, 0원 포함 여부, 표시 행수 등의 로컬 필터를 제공할 수 있다.
- 표시 행수는 100·300·500행 등 제한된 선택값을 사용한다.
- 필터 조작은 기존 facts와 상세 rows를 재사용하며 DB를 다시 조회하지 않는다.
- Excel은 권한을 확인한 뒤 준비와 다운로드를 분리한다.
- Excel은 화면 표시 단위와 관계없이 원 단위 원본 숫자를 유지한다.
- compact snapshot에는 대용량 `risk_detail_rows`, Excel bytes, 상호작용 widget을 저장하지 않는다.
- 다른 채팅방으로 이동했다가 복귀하면 저장된 Dashboard는 compact 읽기 전용으로 표시한다.

## 8. 데이터 원천과 적용 규칙

| 목적 | 원천 | 주요 필드/규칙 |
|---|---|---|
| 제품·제약사·발주처·분류 | `Rddbc040` | 제품코드, 제품그룹·구분·분류, 제약사, 발주처 `Rd04_Orven_Cd` |
| 입고 | `Rddbc110` | 입고일 `Rd11_In_YyMmDd`, 매입처, 재고위치, 제품, 전체 입출고 Tcode |
| 출고 | `Rddbc120` | 출고일 `Rd12_Out_YyMmDd`, 매출처, 재고위치, 제품, 전체 입출고 Tcode |
| 월 실재고 | `Rddbc210` | 제품, 재고위치, 년월, 매입처, 재고적용처, 전체 입출고 Tcode |
| 월 장부재고 | `Rddbc220` | 제품, 재고위치, 년월, 매입처, 재고적용처, 전체 입출고 Tcode |
| 코드명 | `Rddbc010` | 그룹코드·상세코드에 대한 명칭 |

대표 매입처는 입력한 기준일수의 정상 입고수량이 가장 큰 실제 매입처로 정하며 기간 내 입고가 없을 때만 제품마스터 발주처로 보완한다.

모든 조건값은 명칭이 아니라 코드로 저장·전달한다. 입출고구분·제품분류 등 코드 조건은 입고·출고·재고 원천 모두에 같은 의미로 적용되는지 회귀 데이터로 확인한다.

현재고 조회는 저장재고의 현재 상태를 보여 주므로 저장 profile의 `io_gu_list`를
적용하지 않는다. 이 예외는 현재고 조회에만 적용하며, 실재고/장부재고 계산에
사용하는 기존 입출고구분 prefix 제외 규칙은 변경하지 않는다.

## 9. 화면 동작·성능·저장 원칙

- 조회 버튼을 누를 때 공통 기초집계 facts를 한 번 생성하고 카드·그래프·조치목록·상세표가 이를 재사용한다.
- 정상 Dashboard의 logical source 계약은 `source_call_count=3`이다: `sales`, `stock`, `inbound`.
- physical query 수는 각 logical source 내부의 SQL 실행 구조에 따라 달라질 수 있으며 `source_call_count`와 동일한 의미로 사용하지 않는다.
- 같은 조건에서 카드 접기·펼치기, 표시단위 전환, 상세 필터, 조치 목록 렌더는 DB를 다시 조회하지 않는다.
- 기간·재고기준·필터·임계값이 바뀔 때만 facts를 다시 생성한다.
- 상세 보기 자체는 Dashboard facts를 다시 계산하지 않고 기존 대상 KPI/SIMS 조회 경로만 1회 실행한다.
- 최초 조회 목표는 운영 DB 기준 약 18초 이내로 관리하고 동일 결과의 화면 조작은 1초 내외를 목표로 한다.
- 결과에는 적용 조건, 데이터 기준일, 자료부족 여부를 항상 남긴다.
- Dashboard event ID는 조회당 한 번 생성하여 primary cache, payload, compact snapshot, partition 저장까지 동일하게 유지한다.
- Dashboard와 일반 SIMS 결과는 생성 시간순으로 렌더한다.
- 최신 현재 세션 Dashboard만 해당 메시지 위치에서 primary로 렌더하고 과거 결과는 compact로 렌더한다.
- 다른 방 이동 또는 회사 불일치 시 primary/detail/Excel 상태를 노출하지 않는다.
- compact snapshot에는 대용량 원시 rows나 Excel bytes를 넣지 않는다.
- callback 내부의 명시적 rerun에 의존하지 않는다.
- Legacy Dashboard는 현재 공식 운영 화면으로 유지한다.
- V2 preview는 운영 화면에서 비노출·비활성 상태이며 별도 승인과 회귀 전에는 Legacy를 대체하지 않는다.

## 10. 구현 순서와 완료 기준

### 10.1 구현 순서

1. **날짜·공통 조건과 Default**
   - 기본 날짜, 내부 3개월 추세, 복수선택·임계값·표시단위, 회사별 Default 저장·갱신
2. **공통 facts와 재고위험**
   - 매출·재고 facts, 준비율·부족·과잉 후보·수요급증·대표 매입처 위험
3. **위험 상세와 Excel**
   - primary 상세표, 로컬 필터, 권한 기반 Excel, compact snapshot
4. **채팅·세션 안정화**
   - event ID 단일성, 시간순 렌더, primary/compact 분리, 방 전환·패널 상태
5. **오늘의 조치와 drill-down**
   - 결정론적 조치 facts, 최대 10행, 판정 기준, one-shot 상세 연결
6. **Dashboard·KPI·NLQ Default 연결**
   - 동일 Default 초기값, NLQ 명시조건 우선, 회사 격리
7. **매입 일자 facts**
   - 정상 입고일, 경과일, 회전일, 입고 지연, 입력 기준일수 대표 매입처
8. **재고 확장**
   - 재고커버일, 저활성 세부 근거, 장부/실재고 비교
9. **최종 시각화와 업무 브리핑**
   - 카드 4~6개, 확정 매출 막대형, 매입 추세, 위험 분포, Top 10, 업무 브리핑
10. **문서·회귀·운영 마감**
    - 전체 자동 회귀, 사용자 수동 테스트, 문서 동기화, main 병합, 안정 태그, 2호기 배포

### 10.2 필수 합격 기준

- 복수 선택한 거래처·제품·입출고 전체 Tcode가 SQL과 결과 요약에 정확히 반영된다.
- 실재고/장부재고 선택이 재고수량·금액·준비율·위험 판정에 일관되게 적용된다.
- 비관리자는 Default 저장 UI를 볼 수 없고 정상 사용자는 임시 조건 조회가 가능하다.
- 회사 Default가 Dashboard·KPI·NLQ의 초기값에 동일하게 적용된다.
- NLQ의 명시 조건이 Default보다 우선한다.
- 시작월 첫 달부터 최근 3개월 추세가 계산되며 보조 3개월이 완료월 평균·합계에 섞이지 않는다.
- Dashboard logical source는 정상 경로에서 `source_call_count=3`을 유지한다.
- facts 유효행이 0건이면 `no_data`/tableless만 표시하고 빈 Dashboard를 성공으로 렌더하지 않는다.
- 오늘의 조치는 최대 10건이고 동일 품목·동일 원인이 중복되지 않는다.
- 최신 primary에서만 상세 버튼이 보이고 compact에서는 읽기 전용이다.
- 상세 버튼 1회 클릭으로 대상 조회와 채팅 push가 각각 1회만 실행된다.
- 회사·방·stale event 불일치 handoff는 fail-closed로 폐기된다.
- 평가월은 월 달성률과 일자 기준 달성률을 함께 표시한다.
- 금액 표시 단위가 Dashboard 화면 전체에 일관되게 적용된다.
- Excel은 표시단위와 무관하게 원 단위 원본을 유지한다.
- callback 내부 명시적 rerun 경고와 duplicate widget key가 발생하지 않는다.
