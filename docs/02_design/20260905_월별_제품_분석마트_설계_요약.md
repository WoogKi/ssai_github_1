# SIMS AI 월별 제품 분석마트 설계 요약

- 기준일: 2026-09-05
- 기준 브랜치: `feat/dashboard-stock-extension-20260727`
- 기준 커밋: `ddd4530e190d97beae88849db6202851e600e764`
- 문서 상태: 설계 기록
- 구현 상태: 미구현

## 1. 목적과 활용처

월별 제품 분석마트는 회사·제품·기준월·재고위치 범위의 입출고, 원가,
이익과 등급을 재현 가능한 형태로 보존하는 공통 분석 기반이다. 다음 기능이
각자 원천 ERP를 다시 해석하지 않고 동일한 계산 계약을 재사용하는 것을
목표로 한다.

- 기존 3개월 출고빈도 Snapshot 재현 및 장기 추세 비교
- 제품별 출고빈도, 신규품목, 이익과 이익기여 분석
- 계약단가 검토를 위한 제품·거래상대방별 단가 이력 확장
- 발주 판단을 위한 수요, 빈도, 신규 여부와 재고위치별 기초 fact

이 문서는 DB 생성이나 운영 전환 승인이 아니다. 현재는 테이블 구조와 계산
경계를 기록하는 단계이며, 미결정 정책을 승인한 뒤 별도 구현·검증한다.

## 2. 공통 범위

- 기본 grain: 회사 + 기준월 + 제품 + 재고위치 + 명시적 scope
- 운영 분석 window: 최근 완료월 최대 12개월
- history retention: 24개월 기본, 비교·감사 필요 시 36개월로 확장 가능
- `scope_fingerprint`, source watermark, schema/algorithm version, provenance를
  모든 generation에서 보존한다.
- 동일 회사·평가월·scope의 재생성은 기존 승인본을 변경하지 않고 새
  generation으로 발행한다.
- 최초 정상 입고 이력은 12개월 window 밖의 과거도 필요하므로 월 fact와
  분리해 유지한다.

## 3. 권장 테이블 구조

### `mart.product_month_manifest`

분석마트 생성·승인·게시 단위다.

- PK: `manifest_id`
- generation unique key:
  `company_id + evaluation_month + scope_fingerprint + schema_version + algorithm_version + generation_no`
- 주요 속성: 분석 시작/종료월, 상태, 승인 상태, source revision,
  Rddbc040/110/120 watermark와 fingerprint, source mode, 생성·승인·게시 시각,
  row count, checksum
- 동일 identity에서 CURRENT/PUBLISHED generation은 하나만 허용한다.

### `mart.product_month_scope_stock`

manifest가 포함한 재고위치를 명시적으로 보존한다.

- PK: `manifest_id + stock_code`
- fingerprint만으로 숨겨진 범위가 생기지 않도록 scope 구성요소를 함께 기록한다.

### `mart.product_month_fact`

월별 기초 fact다.

- PK: `manifest_id + basis_month + product_code + stock_code`
- 정상 입고: 수량, 공급가액, event 수, 입고일 수
- 정상 출고: 수량, 출고횟수, 출고일 수
- 매출반품: signed 수량, 양수 금액 magnitude, signed 원가
- 순매출, 실제/장부 원가, 선택 원가, 총이익
- 원가 기준, 원가 coverage, 누락 행수, 반품 원가 방식
- source row count, 품질 상태, row checksum

원가 관련 권장 컬럼은 다음 계약을 구분할 수 있어야 한다.

- `book_cogs_amount`, `actual_cogs_amount`, `selected_cogs_amount`
- `selected_cost_basis_code`: `BOOK_FINAL`, `ACTUAL_FALLBACK`, `MIXED`, `MISSING`
- `cost_coverage_pct`, `cost_missing_row_count`
- `return_cogs_book_signed`, `return_cogs_actual_signed`
- `return_cost_method`: `LINE_STORED`, `MONTH_WEIGHTED_ESTIMATE`, `MISSING`
- `estimated_return_cogs_amount`
- `official_profit_eligible`, `profit_quality_status`

추정 원가는 공식 원가 컬럼과 합치지 않는다.

### `mart.product_scope_lifecycle`

제품의 최초 정상 입고 이력을 보존한다.

- unique key: `company_id + scope_fingerprint + product_code`
- 주요 속성: 최초 정상 입고일/월, 관측 완료일, source watermark/fingerprint,
  algorithm version, lifecycle 상태
- 월 fact의 24/36개월 retention과 별도로 유지한다.

### `mart.product_month_grade`

평가월 기준 제품 등급 projection이다.

- PK: `manifest_id + evaluation_month + product_code`
- 직전 3개월 출고수량·출고횟수
- 출고빈도등급 `A~E`, `X`, `F`
- 실현 매입단가·판매단가, 이익률, 제품 이익등급 `A~E/F`
- 총이익액, 기여율, 누적기여율, 이익기여등급 `A~E`
- 원가 기준/coverage, 공식 산정 가능 여부, 등급 사유, 임계값 version

### `mart.product_month_counterparty_fact` 선택 확장

계약단가와 발주에서 거래상대방 단위가 필요할 때 추가한다.

- grain: manifest + 월 + 제품 + 재고위치 + 상대방 역할 + 상대방 코드
- 상대방 역할은 매입처와 거래처를 명시적으로 구분한다.
- 계약단가 적용기간은 별도 effective-period contract로 연결한다.
- 제품 월 fact에 상대방을 직접 섞어 중복 집계를 만들지 않는다.

## 4. 계산 계약

### 출고빈도

- 정상 출고 계약과 기존 event dedup을 재사용한다.
- 출고빈도는 출고수량이 아니라 **출고횟수** 기준이다.
- 월별 출고횟수를 직전 완료 3개월 동안 합산한다.
- 기존 cumulative-before 기여 구간으로 `A~E`를 산정한다.
- 정상 출고 0회는 `X`다.
- 제품 universe와 scope가 같아야 기존 3개월 Snapshot을 재현할 수 있다.

### 신규품목 `F`

- 최초 정상 입고월을 `M0`로 정의한다.
- `M0`, `M0+1`, `M0+2`의 3개월을 신규기간으로 본다.
- 신규기간에는 출고빈도등급과 제품 이익등급을 `F`로 표시한다.
- 이익기여등급은 실제 총이익 기여를 나타내므로 `F`로 덮지 않고 `A~E`를 유지한다.
- 최초 정상 입고월이 신뢰 가능하지 않으면 임의로 `F`를 부여하지 않고
  `INSUFFICIENT`로 처리한다.

정상 입고는 기존 계약인 Gcode `0012`, Tcode `001/002`, 양수 수량과 유효한
`YYYYMMDD` 날짜를 사용한다. 미래일, 비정상 날짜와 입고반품은 제외한다.

### 제품 이익등급

- 의미: 매입단가 대비 제품 이익률
- 후보식:
  `(실현판매단가 - 실현매입단가) / 실현매입단가 * 100`
- 등급: 절대기준 `A~E`, 신규 3개월 `F`
- 매입단가가 0 이하이거나 승인된 원가 coverage를 충족하지 못하면 공식
  등급을 만들지 않는다.
- `A~E` 절대 임계값은 설정 version으로 관리하며 아직 확정되지 않았다.

### 이익기여등급

- 제품별 총이익액을 scope 내에서 내림차순 정렬한다.
- 양의 총이익 pool에 대한 누적기여 방식으로 `A~E`를 산정한다.
- 동률은 cumulative-before 방식으로 안정적으로 처리한다.
- 0 또는 음수 총이익은 손실 상태를 별도 보존한다.
- 누적 구간 임계값은 아직 확정되지 않았다.

### 원가 우선순위

- 1순위 후보: `Rd12_Fin_In_Unit_Cost`(장부입고단가)
- 2순위 후보: `Rd12_In_Unit_Cost`(실입고단가)
- 둘 다 없으면 `MISSING`; 판매단가, 제품마스터단가 또는 0으로 대체하지 않는다.

월별 회계성 이익은 확정 공급가액과 장부입고단가의 대칭성이 가장 높으므로
`Fin_In` 우선을 권고한다. 다만 운영 입출고와 현재고는 `In_Unit_Cost`를 사용하고
두 값이 실제로 다른 행이 존재하므로, 두 원가를 모두 보존하고 fallback 여부를
명시해야 한다.

### 매출반품 원가

- 반품 line 자체의 저장 원가를 정상 출고와 같은 우선순위로 선택한다.
- 반품 수량의 signed value와 선택 원가를 곱해 COGS를 역방향으로 반영한다.
- `Rd12_Re_*`는 수주 키이며 원출고 PK가 아니다.
- 제품·거래처·수량·제조번호 유사성에 의한 원출고 추정 매칭은 금지한다.
- 반품 line 원가가 없을 때 월 가중평균원가는 별도 추정값으로만 저장할 수
  있으며, 승인 전에는 공식 총이익과 등급에 포함하지 않는다.

## 5. 확정 사항

- 운영 분석 window는 완료월 기준 최대 12개월이다.
- history retention은 24개월을 기본으로 하고 필요 시 36개월로 확장한다.
- manifest, scope-stock, month fact, lifecycle, grade를 핵심 구조로 사용한다.
- 계약단가·발주는 counterparty/effective-period grain으로 별도 확장한다.
- 출고빈도는 출고횟수 기준이며 `A~E/X + F`를 사용한다.
- 신규품목 `F`는 최초 정상 입고월 포함 3개월이다.
- 제품 이익등급은 매입단가 대비 이익률 `A~E/F`다.
- 이익기여등급은 총이익액 누적기여 기준 `A~E`다.
- 원가는 `Fin_In` 우선, `In` fallback 후보로 두 값을 모두 보존한다.
- 반품은 반품 line 자체 원가의 signed reversal을 사용한다.
- 원출고 추정 매칭을 하지 않는다.
- 원가가 불충분하면 공식 이익등급은 fail-closed다.
- scope, fingerprint, watermark, version과 provenance를 보존한다.

## 6. 미결정 사항

구현 전에 다음 항목의 업무 승인이 필요하다.

1. `Fin_In` 누락 시 `In` fallback을 공식 이익등급에 허용할지
2. 공식 등급 산정을 위한 최소 원가 coverage
3. 반품 원가 누락 시 월 가중평균 추정값을 공식값으로 승격할지
4. `Quantity`와 `Oquantity`에 같은 원가를 적용할지
5. 제품 이익률의 공식 분모와 `A~E` 절대 임계값
6. 이익기여등급의 누적기여 구간
7. 최초 정상 입고를 회사 전체 scope와 재고위치 scope 중 어떤 기준으로 공시할지
8. counterparty fact를 1차 구현에 포함할지

## 7. 구현 전제와 순서

현재 구조를 크게 변경해야 하는 blocker는 없다. 기존 Snapshot 옆에 새로운
immutable mart generation을 추가하고 다음 순서로 진행한다.

1. manifest/scope/lifecycle/month fact 스키마와 fixture 확정
2. 정상 입출고 월 집계 및 기존 3개월 Snapshot exact-equality Gate
3. 최초 정상 입고와 `F` projection
4. 승인된 원가·coverage·반품 원가 계약 적용
5. 제품 이익등급과 이익기여등급 적용
6. counterparty/effective-period 확장 후 계약단가·발주 연결

구현 완료 조건에는 회사/scope 격리, 12개월 분석 재현, 24/36개월 retention,
source watermark와 checksum, 원가 누락 fail-closed, 반품 포함 순매출·COGS·총이익
equality가 포함되어야 한다.
