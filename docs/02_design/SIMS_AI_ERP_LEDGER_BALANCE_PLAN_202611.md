# SIMS ERP 거래처 장부·수금·지급·잔액관리 개발계획

**지위:** [공식 로드맵 v2.5](../00_roadmap/SIMS_AI_PLATFORM_MASTER_ROADMAP_v2.5_20261027.md)의 Phase 4/P4-01~02 및 S03-06 공식 개발계획. 실제 ERP 테이블·잔액 규칙·DB 조회 승인은 별도다. 기존 계획의 포괄적인 "회계 조회" 표현을 실제 업무 영역인 **SIMS ERP 매입·매출 및 거래처 장부·수금·지급·잔액관리**로 정정한다. 이는 범위 명세이며 ERP 테이블/잔액식의 확정이 아니다. [공식 로드맵 v2.5](../00_roadmap/SIMS_AI_PLATFORM_MASTER_ROADMAP_v2.5_20261027.md) 참조.

## 업무 흐름과 현황

| 연결 | 읽기 기능 후보 | 현재 확인 상태 |
| --- | --- | --- |
| 매출 → 매출처 장부 → 입금 → 미수금 | 매출·입금 조회, 거래처 원장, 전월 이월·잔액 변동·미수금 | 매출/출고 조회 서비스는 존재. 장부·입금·미수금의 동일 원천/잔액 계약 및 운영 완료 근거는 이번 검토에서 확인되지 않음 |
| 매입 → 매입처 장부 → 출금 → 미출금·미지급잔액 | 매입·출금 조회, 거래처 원장, 전월 이월·잔액 변동·미지급 | 입고/발주 및 가격 근거 서비스는 존재. 거래처 장부·지급/미출금의 연결 및 산식은 미확인 |

제품재고장(`stock_ledger.py`)은 거래처 장부의 구현 증거가 아니다. 구현된 조회와 신규 장부 조회를 동일 완료 기능으로 묶지 않는다. 명세서 금액·확정금액·세금계산서·입출금·장부잔액도 별개 지표다.

## 선행 계약 조사

1. ERP의 매출/매입 전표, 거래처, 입금/출금, 장부 잔액 원천과 실제 조인키·전표상태·회사 경계를 소유자/DB 사전·제한 표본으로 확인한다. 테이블명을 추정해 설계에 박지 않는다.
2. 전월 이월, 조회 기준일과 거래처 장부기간, 원금·세액·확정액, 반품·취소·상계·조정, 입금/지급 배분, 동일 거래처의 역할 전환, 음수/부분 수금과 소급 수정의 계약을 문서화한다.
3. 매출처 미수금과 매입처 미출금/미지급잔액이 어느 조회 시점·상태의 값인지 정의한다. R210/R220 매출·실재고 정책 및 미결 거래는 별도 결정 전 현행 의미를 유지한다. 확인하지 않은 잔액 계산식을 만들지 않는다.
4. 권한은 회사·사용자·거래처 범위와 금액 민감도까지 검증한다. 조회 전체/표시행, 기간·잔액 시점, 원천 조회 횟수 및 다운로드 접근 로그를 계약에 포함한다.

## 단계별 읽기 전용 구현 계획

| 단계 | 기능 | 완료 기준 |
| --- | --- | --- |
| L1 원천 계약 | 매입·매출 및 입금·출금 각각의 원천/연결키/이월 규칙 확정 | 제한 표본의 ERP 원화 Decimal Exact, 부호·취소/반품/상계 사례, 회사/권한 경계 승인 |
| L2 명세 조회 | 거래처·기간별 매입/매출, 입금/출금, 전표 상세와 현재표/다운로드 | SQL 조건과 화면·Excel 동일, 전체/표시행 분리, NLQ 공식 사례 Gate |
| L3 장부 | 거래처별 원장과 기간별 집계·전월 이월·잔액 변동 | 원천 장부와 시작/증감/마감 잔액 Exact, 거래처 역할·상계/조정 사례 검증 |
| L4 분석 | 미수금·미출금/미지급잔액, 후속분석 | 기준일·원천/확정 범위 표기, 허위 합계/이월 차단, 권한/성능 회귀 |

**제외:** 경비·비용·분개·계정과목·재무제표 및 자동 입출금/전표 쓰기. 수금·지급 예측은 L3/L4의 정확한 시계열 계약이 확정된 뒤 Phase 5 별도 과제다. 11~12월 일정은 계약 확인과 작은 조회 단위 개발의 제안이며 운영 DB 접근·개발 승인을 대체하지 않는다.
